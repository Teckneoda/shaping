# Planning State — PAL Image Uploads Still Tied to Legacy CAPI

## Identified So Far

**Architecture chosen (working solution, reworked 2026-09-01):** staged object + **async Pub/Sub attach**. A GraphQL get-signed-URL mutation (`beginListingPhotoUpload`, routed by vertical) returns a signed POST policy that pins the attach contract as object metadata → browser uploads to a private staging bucket → OBJECT_FINALIZE → Pub/Sub → per-vertical attach subscriber (classifieds / cars) does authz, invokes image-http-rest by reference (displayed rendition first), writes back to the listing → the front end **polls** for "attached". This **supersedes the synchronous-GraphQL-commit design** of the earlier passes (and of the design doc §3): the sync-commit's advantages (immediate feedback, no reorder-before-attach race) are re-created via the poll contract ("done" = attached) and a final FE reorder. Full feature breakdown in `Features.md`; service-by-service changes in `Services.md`.

**The proposed architecture already exists twice in marketplace-backend** — listing-jobs-http-rest (staging keys `staging/{memberId}/{uuid}/...`, POST policy w/ size condition + metadata pinning, storage-key ownership verification, private-bucket TF with custom-time lifecycle) and the video pipeline (`GenerateSignedPostPolicyV4` signed-URL generation, OBJECT_FINALIZE→Pub/Sub, vertical attach subscriber — now the direct template rather than a rejected alternative). The genuinely new work: (a) image-http-rest accepting a source by object reference + the priority/deferred rendition split, (b) the attach subscribers + service-caller photo endpoints, (c) the separate cars photo deployment.

**Fifth pass (2026-09-01) — shaping-meeting outcomes + scope decisions.** Meeting (transcript in this folder: `PAL image uploads - shaping questions.vtt`; Chris Pies + Spencer Dickson, Rebekah Fowles, Abe Fawson) confirmed: signed-URL-via-GraphQL + direct bucket upload (ADR-consistent; videos/profiles precedent), ksl-api/Capi are thin wrappers around image-http-rest, FE work minimal and wanted (retires the DR-009 exceptions), explicit ordering needed (parallel uploads finish out of order), stepper-blocks-Next behavior, editor is destructive crop/rotate with no saved editor state, videos stay separate. **Four scope decisions taken by Chris after comparing meeting vs package:**
1. **Async Pub/Sub attach** replaces the synchronous commit (adopts the previously rejected profiles/video pattern; reopens done-signal + ordering as design items → Q21–Q25, reshaped Q19).
2. **Separate cars deployment** (reverses Q5's 8/26 registry resolution): own signed-URL endpoint + attach subscriber; deliberately disposable — retired when cars data merges into classifieds. listing-http-rest stays pure-Classifieds; no vertical registry.
3. **Q11 rendition split pulled into v1**: cut `classified/adPic1` (+ mobile fallback) before attach, defer the rest async — promotes the image-http-rest renditions-PATCH service-JWT fix to required scope.
4. **Simplified replace edit**: edit = new image at the old photo's position + delete old bytes after the swap. No two-file assembly, no `cropMD5`/`userEdit`/`cropTime`. Resolves Q8/Q18/Q20; Classifieds and Cars edits become identical.
**In-meeting non-goals recorded (F9):** no unification with the profile images-service / "media uploader" (t-shirt sizes + CDN resize-on-request — "argue for later"); no GraphQL subscriptions for completion (poll first, don't preclude); no move-on-while-uploading progress modal (needs product buy-off). **Definition of done clarified:** legacy "elimination" = the PAL/web path stops using Capi/ksl-api; the Capi endpoint lives on as a shim for old apps. **Correction:** cars is not "a different Mongo database" — `classifieds.auto`, same cluster+DB.

**Fourth-pass finding (2026-09-01, commit-position concern verified):** Stephen Sagers (design-doc author) left an unresolved comment on the framing doc (2026-09-01) worrying that commit-with-position could produce non-sequential photo-array numbering that PHP would serialize as a map. **Verified unreachable through the proposed write shapes**: no code in Capi, ksl-api, or listing-http-rest writes `photo.<N>` by numeric index — every write is `$push`/`$pull` or whole-dense-array `$set`; `$push`+`$position` is a splice and cannot create holes; a partial batch failure yields a *shorter dense array*, never gaps; photo identity is the `id` field everywhere, never the index. The remembered bug is his own 2020 fix (Capi `ba021453`): PHP `unset()` without `array_values()` before a whole-field `$set` → BSON document keys "0","2","3" → `json_encode` map; the patch survives at [ListingController.php:1741-1743](file:///Users/cpies/code/shaping/Research%20Repos/Legacy/m-ksl-classifieds-api/src/Controller/ListingController.php#L1741-L1743) (ksl-api mirror :1803-1804). Residual hazards recorded in Features F2: (a) PHP stays an active writer through the transition — any hole-making PHP edit that loses its `array_values()` reintroduces the bug; latent machinery in [AbstractCollection.php:90-109](file:///Users/cpies/code/shaping/Research%20Repos/Legacy/m-ksl-classifieds-api/src/Db/Mongo/AbstractCollection.php#L90-L109) would explode a sparse array into dotted `photo.N` `$set`s if ever wired to listings; (b) Go's read path **hard-fails (500) on a map-shaped `photo`** — bare `.Decode` at [store/listing.go:157](file:///Users/cpies/code/shaping/Research%20Repos/marketplace-backend/apps/listing/services/listing-http-rest/internal/store/listing.go#L157), no tolerance shim — which is the blast radius making the dense-array invariant load-bearing. Decision handle: Q19 (reshaped for async — see below; the invariant analysis holds unchanged, and out-of-order async arrival makes it *more* important).

**Legacy behavior contract captured** (details + line refs in `Features.md`): synchronous per-image response with URL (legacy only — the new browser path is poll-based); ~7 pre-generated renditions (Classifieds) / 11 (Cars); atomic `$push` append; edit-in-place with cropMD5/userEdit/cropTime + new-URL cache-bust + async old-file cleanup (2026-09-01: crop metadata deliberately dropped — simplified replace); reorder by URL list with fuzzy filename match; delete dual-path (GCS batch-delete vs legacy-S3 queue); Cars extras: `backlot.photoOrder` parallel array, per-photo `description`, `preMd5`, ES sync via change stream, and **no server-side edit flow** (see the in-flight `CAR_pal_photo_editor` finding above — the client-side fake makes edit a live requirement).
